## 四、加密方案

### 核心决策

- 只需加密**少数几篇**私密文章，不是全部
- 加密模型：**客户端加密**（构建时生成密文，浏览器中用 JS 解密，密码由访问者输入）
- 安全定位：**防君子不防小人**。纯静态前端加密无法阻止下载密文后离线暴力破解，但对于个人博客内容的敏感级别，这个强度足够（没有人会花算力来爆破你的博客）

### 技术原理（修正最初的理解错误）

**错误理解：** "用 SHA256 加密文章，密码不对就解析出错误内容。"

**SHA256 是哈希函数，不是加密算法。** 哈希是单向的，不能用于解密。正确的流程：

```
用户输入密码
    ↓
密钥派生函数（PBKDF2 / Argon2id）  ← 不能用裸 SHA256，太容易被暴力破解
    ↓
派生出一个 AES 密钥
    ↓
用 AES 解密密文
    ↓
密码正确 → 明文
密码错误 → 乱码 / 解密失败
```

**已有的现成工具：** StatiCrypt、PageCrypt 等——不需要自己实现加密逻辑。

### 身份模型（原稿有误，已修正）

- 原稿提出三层身份（游客 / X / Y），其中 X 的答案是"网名"——**这是安全上的幻觉**，网名是公开信息，不能作为秘密
- 实际模型应简化为：**公开文章（所有人可见）+ 加密文章（有密码的人可见）**
- 使用强密码，不是网名或真名

## 五、技术选型

### 核心方案：静态站点生成器（SSG）

**SSG 是什么：**

静态站点生成器读入你的 markdown 文件，套上模板，在构建时一次性生成全部 HTML 页面。没有数据库，没有后端运行时，所有页面都是普通的 `.html` 文件。部署到任何静态文件托管（GitHub Pages、Vercel、Cloudflare Pages、甚至随便一个 Nginx 服务器）。

SSG 的起源可以追溯到 2008 年的 Jekyll——GitHub 联合创始人 Tom Preston-Werner 创建它时的核心洞见是：**博客的内容只在作者发布新文章时才变化，那就不需要每次用户访问都查数据库、渲染模板。在发文章的时候一次性生成好 HTML，用户访问时直接返回静态文件即可。**

### 候选方案

| 方案 | 语言 | 构建速度 | 模板生态 | 上手难度 | 评价 |
|------|------|----------|----------|----------|------|
| **Hugo** | Go | 极快（毫秒级） | 300+ 免费主题 | 低 | **首选推荐**。下载一个二进制文件即可，选主题 → 扔文章 → 一条命令生成 |
| **Astro** | JS | 快 | 组件化，现代 | 中 | 更灵活，需要 Node.js，适合愿意写一些前端的人 |
| Jekyll | Ruby | 一般 | 丰富 | 中 | GitHub Pages 原生支持，但本地环境配置麻烦 |
| Zola | Rust | 快 | 主题较少 | 低 | Hugo 的 Rust 替代品 |

### 推荐：Hugo

- 不需要安装 npm/pip 等任何包管理器。下载一个 `.exe` 就能用
- 一条 `hugo new site` 创建项目，把 markdown 扔进 `content/`，选主题，`hugo server` 本地预览
- GitHub Pages 部署有现成的 GitHub Actions 模板
- 模板语法（Go template）简单，后期可以自己改

## 六、"从零手搓 vs 用组件"的结论

**不要从零手搓 HTML。** 50 篇文章手写 HTML 是疯了。

正确的路径：

1. **选 SSG**（Hugo）——这是你的"框架"，替你处理文章→HTML 的转换
2. **选主题**（Hugo Themes Gallery 里挑）——这是你的"外观"
3. **后期自定义**——当你跑起来之后，再逐步修改模板的 CSS/HTML，让网站变成你自己的

**组件从哪来：**
- SSG 主题市场（如 themes.gohugo.io）
- UI 组件库（如 Tailwind UI, shadcn/ui）
- 别人博客的开源代码（GitHub 上搜 "blog hugo" 或 "blog astro"）
- 看到别人博客上喜欢的东西，浏览器 F12 开发者工具直接看代码，抄过来改

**能不能自定义？** 能。没有一个模板是锁死的。但前提是你先"跑起来"——裸奔的默认主题也比对着抽象问题发呆强。

## 七、在 AI 时代学前端的意义

### 核心判断

**AI 降低了写代码的门槛，但没有降低做判断的门槛。**

前端现在是 AI 最擅长的领域之一（v0、bolt.new 等），如果你学前端的目的仅仅是"会做个网页"，AI 确实能替代你。但以下两件事 AI 替代不了：

**1. 审美判断力。** AI 能生成十套配色方案，但它不知道哪个好。你需要有能力说"这个间距不对""那个阴影太重"。这种判断力来自你亲手做过、看过、改过。你对 AI 输出的筛选能力，正比于你亲手做过的项目数量。

**2. 掌控感。** 你的博客是你在这个互联网上唯一完全属于自己的地盘。平台会死，政策会变——但如果你知道 HTML/CSS/JS 怎么工作，你的内容永远可以迁移到任何托管平台。前端知识 = 对自己数字资产的最终控制权。

### 对你的实际建议

- **对写博客：** 你只需要学够用的前端——HTML 骨架、CSS 布局（flexbox/grid）、基本的模板语法。认真学，**两到三周**。
- **对职业生涯：** 你不需要成为前端工程师，但如果你连一个 flexbox 布局都看不懂，你和前端同事合作时话语权就矮一截。这是工程沟通成本。
- **学习顺序：不要先学全会了再造车。** 先把网站跑起来（Hugo + 主题），然后边改边学。你的目标不是成为前端工程师，是成为一个能掌控自己网站的人。
