事情要从我那台 HP 笔记本说起。

它实在太重了。重到什么程度呢？重到我每次想把它从学校带回家、或者带去别的地方时，都会在心里先进行一次微小但真实的斗争。到底值不值得背？今天真的非带不可吗？如果只是想写点东西，有必要背着这么大一个家伙跑来跑去吗？

于是，一个非常自然的想法就出现了：我需要一台便携设备。

---

## 一开始我以为自己需要的是一台新笔记本

既然想要便携，最先进入我的视野的自然是 MacBook 和 MacBook Air。

说实话，这几乎是一个不用思考的第一候选。轻薄、续航好、外观也舒服，很多人对它的评价也很高。如果只是从“便携写作工具”这个角度看，MacBook 系列简直就是标准答案，也难怪是很多精致人的标配。

但问题也很现实，苹果的产品很贵（性能溢价）。

尤其是在当下，内存涨价带动了一波苹果产品价格上浮，而苹果本身又一直处于“即使你接受它贵，它还是能比你预期再贵一点”的区间里。再加上生态问题——这个“生态”其实很微妙，它既可能成为购买苹果的理由，也可能成为放弃苹果的理由。你一旦进入，确实能享受到一套相当流畅的体验；但如果你没有完全进入，或者根本不想为了某个单一需求去整体迁移，那它反而会成为一种额外成本。

所以综合下来，苹果方案很快就被我排除了。

排除苹果之后，我就开始在 Windows 阵营里找。联想自然成了重点考察对象。至于 HP——那是最先被排除的，甚至都不是“候选之后排除”，而是从一开始就直接判死刑。这就不得不提我那台堪称灾难体验的惠普笔记本了。我愿称之为“黑屏精灵”。它不仅在使用体验上给我留下了非常深的心理阴影，维修体验更是让我彻底失去耐心。总之，经过那一遭之后，我对 HP 笔记本的态度已经很明确了：这辈子我大概都不想再碰。

于是，我把目光转向了 ThinkPad。

---

## 要不要搞一台二手 ThinkPad 装 Linux

在某一个阶段，我其实已经快把这件事想明白了：如果我买一台便宜一点的机器，再装一个 Linux 系统，那么我对硬件配置的要求其实可以非常低。预算还能再往下压。

想起那种经典梗图：别的电脑（一般是苹果）在娇贵的环境下运行，ThinkPad 却连着一台“变压器”？，仿佛“什么环境都能跑”。这种梗之所以能流行，我想也是因为它背后多少有点现实基础。稍微了解一下之后，我发现 ThinkPad 系列的口碑确实非常能打，尤其是在稳定性、键盘手感、耐用性这些方面，几乎称得上是“老牌生产力工具”的代名词，被公司广泛地采购。

所以那时候，我其实已经初步敲定了一个方案：买一台二手 ThinkPad。值得一提的原因是：正是因为 Thinkpad会被公司广泛地采购，因而公司换生产力工具的时候，也会有大量的老牌 Thinkpad 流入二手市场。

但问题又来了：我对二手市场接触不多，而且说实话，我对二手产品本身一直有一种天然的抵触。不是完全不能接受，而是总会担心看不见的问题，担心踩坑，担心买回来之后才发现“便宜确实有便宜的理由”。

于是这件事就这么搁置了下来。

唉，这个决策其实不是被否定掉的，而是被悬置。它们没有一个明确的“不”，只是因为缺乏足够强的推动力，最后慢慢沉到后台去了。

---

## 暑假回家，我意识到：我从头到尾都想错了

放暑假回家之后，我看到了自己考研时期用过的 iPad 。

那一刻，我有一种非常典型的“柳暗花明”式顿悟感。

我突然意识到：我一直以来想要的，根本不是一台“笔记本电脑”。

我真正需要的，其实只是一个**带键盘的输入设备**。

这几乎等于把我前面所有的思路都推翻了。因为当我重新审视自己的需求时，我发现自己根本没有那么多“电脑需求”。我不需要用它开会，不需要用它做 Office，不需要剪视频，不需要跑代码，不需要处理复杂办公场景。

至少在这个需求链条里，我真正频繁、明确、稳定需要做的事情，只有一件：

**打字。**

更准确地说，是：我想在不方便用电脑的时候，依然能舒服地写东西，而不是用手机在那里艰难敲字。

一旦把需求还原到这个层面，答案就瞬间变得非常清楚了。

我面前这台闲置已久的 iPad，不就是现成的解决方案吗？给它配一个键盘，它不就是一台成本最低、便携性极高、而且我已经拥有的“写作设备”吗？

更妙的是，这台 iPad 平时几乎没被真正利用起来，长期处于一种略显尴尬的闲置状态，某种程度上甚至已经快沦为我妹的 B 站视频启动器了。现在想来，这么一台设备摆在那里，而我却一直在想“我要不要重新买一台轻薄本”，多少有点舍近求远。于是，我简单了解了一下配件，果断下单了键盘。

---

## 设备问题解决之后，真正的问题才开始出现：怎么同步？

硬件一旦解决，新的问题马上就来了：我该怎么在 iPad 上舒服地写东西，并且和电脑之间保持良好的衔接？

最原始、最符合直觉的办法，当然是 QQ 或微信传文件。写完了发给自己，回头在电脑上打开。听起来好像能用，但我吃过这方面的苦，它几乎注定会带来一堆麻烦：

- 版本混乱；
- 经常忘记最新稿到底在哪个设备上；
- 修改之后又得重新发一遍；
- 有时候只是想补一句话，却要来回倒腾；

我没有办法解决同步问题，只是把同步问题伪装成了“传文件”。于是我开始想更“系统”的方案。

我最开始想到的是 iCloud。这个思路其实很自然：既然 iPad 是苹果设备，那我能不能把我的工作目录直接放到云端？只要 workbench 在云上，iOS 端就能直接访问，我写好的内容自动同步到云上，等我有机会回到电脑前，再统一整理、发布就可以了。

这个方案本身并不差，甚至可以说相当符合直觉。但问题在于，我当时的思维方式还是很明显地带着一点 Linux 式的路径依赖。我甚至开始思考：能不能把我 PC 里的 repo 和 iCloud 文件夹建立某种硬链接，或者用一些文件系统层面的技巧把这件事“打通”？它体现出一种典型的技术直觉：当你熟悉底层机制之后，你很容易优先从“系统层面怎么连起来”去想问题。文件系统、目录映射、软链接、硬链接、同步机制、监听变化……

可就在我把这个问题抛给 AI 的时候，它给了我一个堪称“杀死比赛”的答案：

**直接用 GitHub。**

是啊，为什么我第一时间没有想到 GitHub？

我为什么会先想到“把本地目录和云盘打通”？为什么会想到文件系统层面的操作？归根结底，是因为我在试图自己搭一个同步方案。

可问题是，如果一个需求已经如此普遍、如此经典、如此值得被反复解决，那它大概率早就已经被人以更成熟的方式解决过了。而 Git，就是那个早就存在、并且已经被打磨得极其成熟的轮子。

更准确地说，不只是 Git，还有 GitHub 这样的托管平台，以及围绕它建立起来的整套工作流、工具链和跨平台生态。

我后来回头想，自己之所以会冒出前面那些“自己动手把同步做出来”的想法，某种程度上恰恰是因为我长期使用 GitHub，已经在潜移默化中被它影响了思考方式。版本控制、远程仓库、提交、拉取、同步、回退、分支——这些概念早已内化成了我的一部分工作直觉。只不过在那一瞬间，我一开始没有意识到：既然我想要的是“在不同设备上可靠地同步文本并保留修改历史”，那这不就是版本控制系统最擅长的事情吗？

---

## Git 实在是太牛了

Git 它重新定义了我们和文本、和项目、和历史之间的关系。

在没有真正习惯 Git 之前，我们对文件的管理方式通常是这样的：改了就保存，怕丢就另存一份，怕改坏就再复制一份，于是目录里逐渐出现各种让人崩溃的文件名：

- `article.docx`
- `article_new.docx`
- `article_new2.docx`
- `article_final.docx`
- `article_final_final.docx`
- `article_final_really_final.docx`

这其实是一种非常原始的人肉版本管理。它不是不能工作，但它脆弱、混乱，而且完全依赖人的记忆和自觉。

而 Git 提供的是一种完全不同的秩序。

你不再是“保存一个文件”，而是在“记录一次修改”。  
你不再只是“留一个备份”，而是在“维护一段历史”。  
你不再只能在不同版本之间靠猜，而是可以明确知道：我改了什么，什么时候改的，为什么改的，如果现在不满意，我还能退回去。

Git 非常优雅地解决了“跨设备同步”这个问题。我不需要琢磨怎么让某个本地目录神奇地映射到另一个系统，也不需要担心某个聊天窗口里哪份文件才是最新版本。我只需要遵循 Git 的逻辑：在一个设备上修改、提交、推送，在另一个设备上拉取、继续修改。这个过程清晰、可靠，而且有历史可追。

很多伟大的工具都有一个共同特征：它们在你真正用顺手之后，会让你产生一种错觉，好像问题本来就应该这么解决。你甚至会忘记，在没有它的时候，人们其实是在一片混沌中艰难维持秩序。Git 就是这种级别的工具。

---

## 不是 iPad 上没有 Git，而是我一开始没往这个方向想

当我意识到 GitHub 才是最合适的方案之后，剩下的事情就很顺理成章了。

我开始找 iPad 上的 Git 工具，然后发现：当然有。

版本控制从来就不局限于某一个操作系统。它也不应该被局限于某一个操作系统。Git 这种东西，本身就具有非常强的平台中立性。只要有文本文件，只要有仓库，只要有提交与同步的需求，它就能工作。

最后我用上了 Working Copy。

因为我已经熟悉 Git 的基本逻辑了。所以当软件把那些操作——clone、pull、commit、push——以一种适合 iPad 的形式呈现出来时，我几乎没有付出什么额外学习成本，就自然地上手了。

水到渠成

这也是我后来觉得特别有意思的一点：很多时候，一个新工具之所以好上手，一方面是设计者的巧思，把它设计成这样，另一方面还因为你过去积累的知识在这里发生了迁移。

这让我想到很多更普遍的事情。

比如编程语言的学习。你学第二门语言时，虽然语法不同，但很多抽象已经共通了。再比如算法、操作系统、网络、工具链，甚至不仅仅是计算机领域。很多知识的真正价值，未必体现在“它本身能直接解决多少问题”，而体现在它会如何重塑你的思维方式，让你在面对一个新场景时，更快找到结构上的相似性。

说得大一点，学习本身也许就是一种迁移。你在一个地方建立起的理解，会在另一个地方突然发光。很多“灵光一现”，其实都不是凭空出现的，而是旧知识在新情境中的重新组织。

---

## 一个意料之外的收获：iPad 让我写得更专注了

除了同步和输入体验之外，使用 iPad 还有一个我事先完全没预料到的巨大副产品：

它让我写作时变得非常专注。

原因其实很简单。和电脑相比，我的 iPad 上几乎没有那么多会持续打断注意力的东西。除了 B 站和 YouTube 之类的视频软件和装机自带的软件，它几乎不具备其他娱乐功能。因此我被动地变得更加专注了。

如果我的目标就是写东西，这样一个功能极其有限的设备，反而更像一个真正为写作服务的环境。

---

## 最后

回看整件事，我想：

第一，需求要尽量被定义精准。  

第二，别急着自己造轮子。  

第三，好工具会塑造思维。  

第四，学习最大的回报之一，是迁移。  

蓦然回首，如此适合我的需求的东西其实就在我身边，只是我之前并未发觉。好一个“灯下黑”啊。
