我的 AI 工作台：工作流、协作原则，以及可直接复制的提示词。

## 我的工作流

### 读书

阅读时可按章节推进，边读边摘抄；有想法就随手记下。读完整本后，整理摘抄与随记，产出一篇读书笔记（走下面的写作流程）和一篇搬运摘抄。

### 写作

1. **先攒素材。** 尽可能多地把与主题相关的想法记下来——一句话、一段话、别人的话都行。这一步最重要，慢一点也没关系，让主题在“暗时间”里持续发酵。
2. **让 GPT 整理思路。** 把素材交给 GPT（不用 DeepSeek，效果差），让它先问 10–20 个相关问题，你据此补充素材。
3. **再成文。** 效果不理想，就让它继续追问、继续补料；效果尚可，就自己补细节、做润色。
4. **手动 de-AI。** 即便是 GPT，写出来仍有很浓的 AI 味。不要试图让 AI 去 AI 味（自指效果不好），只能自己动手改。
5. **把 AI 当脚手架。** 可以让它故意写长一些，补过渡、做扩展，帮你先把结构搭起来。

### 项目

先建立项目的 hierarchy——列出这个项目应有哪些部分，不必过细，视复杂度而定；再搭一个 minimum viable system，然后开始开发。

## 与 AI 协作

### 定位

- AI 不是我，也不是人。不要假设它“知道我的上下文”，需求必须被精确描述。
- 把 AI 看作一个包含所有可能答案的解空间，提示词是在给答案加约束。约束不充分，它就会“发挥想象力”，给出一个你不想要的解。
- AI 是副驾驶（Copilot），但飞行员（Pilot）仍然是你。它能发挥的上限，取决于你的判断力、专业知识和提问能力。

### 协作

- 赵斌：我和 AI 协作完成一个工作，总是比我或它单独完成要好。这句话有三层：
    1. 你总是可以把事情做得更好。
    2. 任何事情，你都可以寻求 AI 的帮助。
    3. 但要和 AI 协作，而不是把复杂度全部交给它。
- 不要一直给 AI 下命令。像“帮我发一篇 Nature”这种事，显然很难一步做到；更合理的是借助 AI 降低试错、查手册、造轮子的成本，但思考与判断仍由你完成。
- 反过来想，最重要的提示词其实是：**“你需要我做什么，我该如何协助你工作？”** 不知道该做什么时，直接把这个问题交给 AI。
- AI 往往很配合，会要你补充信息；但更多时候，它会基于已有的事实直接展开。意识到这一点，剩下的事就好办了：困惑什么就问，不知道怎么协助，就让它给你派活。

### 起步

- 让 AI 先出计划：Think step by step and build a plan first.
- 绿导师：AI 给了我们一个好的起点。你总是可以现在就开始做点什么，而不是“这篇文章好长，明天再看”。
- 绿导师：面对复杂任务，只要你相信它能完成，并把它说清楚，基本就能做完。AI 时代，你只需要知道能做什么、该做什么，剩下 tedious 的事交给 AI。
- 我在做 X。如果你是这个领域的专家，你会怎么做？被动：学习 Coding Agent 所做的“正确的事”；主动：让 Copilot 不停追问、实时给出建议。
- 人的记忆就像 AI 的工作区上下文。（人的一生能算是一个 repo 吗？）
- Rust 是 AI 时代的未来：严格的编译器迫使程序员在写代码时就考虑边界情况和潜在错误，也能与 AI 无缝对接。

## 提示词

### 基础规则

| 规则 | 目的 |
| --- | --- |
| 用最简洁、最平实的语言回答。 | 降低歧义，便于复用与粘贴。 |
| 只陈述事实与逻辑，禁用比喻/类比/故事。 | 保持客观、可核验与可追溯。 |
| 常识问题直接提问。 | 提高效率，避免过度设定。 |

### 通用框架

角色 + 任务 + 目标 + 背景 + 格式。

| 要素 | 写法要点 | 说明 |
| --- | --- | --- |
| 角色 | “我是 [岗位/领域]，本提示用于 [用途]。” | 固定口径，召回相关知识与风格。 |
| 任务 | 用 1-2 句说明要做什么，先搭框架。 | 先框后细，避免跑题。 |
| 目标 | 定性/定量标准，引用行业/国家/单位指标。 | 可检验、可对齐期望。 |
| 背景 | 已做工作、已有材料、遇到的具体问题与限制。 | 提供足够上下文，减少猜测。 |
| 格式 | 指定输出为表格/清单/段落；字数；层级；禁用词。 | 直接产出可用交付物。 |

### 学术场景

| 场景 | 常见问题 | 优化指令（摘要） |
| --- | --- | --- |
| SCI 文献全文讲解 | 结构松散，层级不清，变成泛泛总结。 | 按论文逻辑讲解：研究背景与问题定义；思路与技术路线；关键方法与设计依据；核心结果及其物理/化学/光学含义；作者认为的创新点与结论；仅客观复述，不引入假设。 |
| 文献配图讲解 | 只描述“看起来是什么”，未对齐正文论证。 | 翻译图题与图注；逐子图说明坐标/要素的物理含义、控制变量与对比关系、在论证中的作用；整图支持的结论；不超出原文结论范围。 |
| 检索相关 SCI 文献 | 检索标准缺失，易“猜文献”。 | 仅列可核验的期刊论文；限定期刊范围；给出题目、作者、期刊、年份；不确定时明确标注，不虚构参考文献。 |

### 要素与风险

| 要素 | 缺失时的风险 |
| --- | --- |
| 输出结构与格式 | 输出不可控、难复用；总结变推测，分析变方案。 |
| 禁止事项 | 虚构文献、数据、实验条件；夸大创新性与结论强度。 |
| 产出物类型 | 无来源的内容被引入，研究决策可能偏离。 |
| 用途与风格 | 风格不匹配，论文用语不规范，组会或审稿时解释不清。 |
| 资料边界 | 推测当事实、讨论当结论，机理解释强度失控。 |
| 来源标注 | 伪确定性：错误结论被当作已证实，后续实验浪费。 |
| 事实与推导 | 停留在概念层，无对照、无指标，难以转化为论证。 |
| 不确定性 | 信息散乱、密度不均，难比较、难引用。 |
| 可落地性 | 出现“看起来对、实际上错”的硬伤。 |

### 编写规则

| 规则 | 要点说明 |
| --- | --- |
| 用行为规则代替愿望描述 | 把“更专业/更深入”改成可执行要求，如必须给证据、步骤或表格字段。 |
| 先写输入契约 | 明确用户要提供的字段，缺少则先询问或列出“缺失信息清单”，不要让模型猜。 |
| 再写输出契约 | 说明交付物类型（清单/表格/报告）、固定小标题与顺序，是否需要简版/详版。 |
| 写清优先级与取舍 | 正确性 > 可执行性 > 简洁；遇到不确定先声明，不强行下结论。 |
| 加不确定/失败策略 | 信息不足→标注不确定并附补充清单；超范围→说明边界并给替代输出。 |
| 用正反例锚定预期 | 提供一个想要的输出和一个不想要的输出，并点明差异点。 |
| 固化语言的禁用词与格式规则 | 如禁用“明显/较大”等空泛词，要求给数值；术语首次中英对照；编号风格固定。 |
| 触发词做模式切换 | 使用“论文模式/组会模式/教学模式”等触发词，避免单一规则套用所有场景。 |

### 要素速查

| 要素 | 作用 |
| --- | --- |
| 角色定位 | 固定专业身份与写作口径，减少发散。 |
| 任务菜单与边界 | 明确能做/不做，控制结论强度。 |
| 输入契约 | 让用户喂对信息，保证可比性与可计算。 |
| 输出契约 | 让输出成为可直接写进论文的交付物。 |
| 质量标准 | 定义“好输出”的判据，提升可信度。 |
| 失败与不确定性策略 | 防止装懂，保证严谨。 |

### 时效性提醒

现在的 AI 日新月异。过去需要自己琢磨、靠经验攒出来的提示词，它已经慢慢学会了，所以上面这些内容有很强的时效性。整理在这里，只是留下一个当下的参照。
